Monitoring Suhu

Recording temperature and humidity at monitoring points across hospital units, and flagging readings that fall outside the standard range.

RoleSystem design & fullstack development
ContextInternship, Azra Hospital (Nov 2025 – May 2026)
TechLaravel, PHP, MySQL
DeliverablesData model, input flow, dashboard, PDF report

01Context & Problem

Rooms and storage areas in a hospital must stay within a set temperature and humidity range. Staff take readings at fixed monitoring points several times a day.

The system needed to make recording quick for staff and make it easy for supervisors to see, per unit and location, which readings were out of range.

02Key Requirements

  • Configurable parameters: parameters (e.g. temperature, humidity) with unit of measure and standard min–max, managed as master data.
  • Monitoring points: points belong to locations and units; each unit is set up with the parameters it must record.
  • Fast input: readings entered per date and time, including inline entry from the table.
  • Out-of-standard detection: the dashboard compares each reading with its standard and lists the ones outside the range.
  • Reporting: charts per period and PDF export.
  • Role-based menu access.

03Design

Data model highlights

  • parameter_suhu with unit and standard min–max
  • titik_pantau and master_lokasi, linked to units
  • setting_unit_suhu defines which parameters each unit / point must record
  • log_monitoring (date, time, unit, point) with detail_monitoring holding one value per parameter

04Key Decisions

  • One log with many detail values, so a new parameter can be added without changing the table structure.
  • Standards stored on the parameter, so the out-of-range rule is defined once and applied everywhere.
